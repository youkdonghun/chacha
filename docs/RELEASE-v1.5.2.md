# Chacha Capture v1.5.2 · 캡처 실패 후 단색 화면 수정

v1.5.1 진단에서 두 모니터의 `BitBlt(CAPTUREBLT)`가 Win32=288로 실패한 뒤 기본 복사만 성공하고, 결과는 단색(`uniform=True`)으로 나타났습니다. 해당 기본 복사를 정상 캡처로 받아들인 경로를 수정했습니다.

- 실패 뒤 `SRCCOPY`만으로 재시도하던 경로를 제거했습니다.
- 기존에 ‘호환 방식’으로 저장했어도 GDI가 실패하면 DXGI GPU 캡처로 한 번 복구합니다. GPU 우선에서 오류가 나면 반대로 GDI를 한 번 시도합니다. 설정을 다시 저장할 필요는 없습니다.
- 복구한 방식과 최초 오류를 진단에 남기며, 미리보기에도 방식 전환을 안내합니다. 두 방식이 모두 실패하면 각각의 오류를 표시합니다.
- 정상 캡처의 회색·흰색·검은색 단색 화면은 그대로 보존합니다. RGB와 불투명도를 보존하는 처리는 유지하며, 화면 색만 보고 실패로 판단하지 않습니다.
- 한글·영문 OCR과 기존 단축키·설정은 유지합니다.

자체 검사 39개와 실제 화면 통합 검사 129개 assertion을 통과했습니다. 288 오류 주입 → 실제 DXGI 화면 읽기 → 영역 선택 → 클립보드 복사까지 픽셀을 확인했습니다. 검증 결과와 환경의 한계는 [검증 기록](VALIDATION.md)에 기록합니다. 사용자의 실제 듀얼 모니터에서 GPU 복구까지 성공하는지는 아직 확인되지 않았습니다.

기존 앱을 트레이에서 종료한 뒤 새 `ChachaCapture.exe`를 실행하거나 **업데이트 확인**을 사용하세요.
